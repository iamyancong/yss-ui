# @yss-ui/create 更新日志

`@yss-ui/create` 与别名包 `create-yss-app` 版本同步，共用本更新日志。

## v1.3.1

`2026-10-13`

### ⚠️ 行为变化与升级说明

| 项 | 以前 | 现在 | 需要做什么 |
| --- | --- | --- | --- |
| 新版本检查缓存 | 查询到的最新版本号在系统临时目录缓存 24 小时，期间不再请求 registry | 去掉 24 小时本地缓存，每次交互运行实时查询最新版本（超时 1.5 秒） | 无需处理，发布新版本后无需清缓存即可收到提示 |
| 切换新版本确认框默认值 | 默认选「否」，直接回车继续使用当前旧版本 | 默认选「是」，直接回车即通过 `npx` 切换到新版本继续创建 | 想继续使用当前旧版本时，在确认框手动选「否」或传 `--no-update-check` |
| 切换新版本下载失败处理 | 仅 `npx` 完全无法启动时回退；`npx` 已启动但下载包失败时直接中断整个创建流程 | 通过子进程启动握手区分「下载阶段失败」与「新版本运行期报错」：下载失败自动告警并退回当前版本继续创建；运行期报错提示可加 `--no-update-check` | 无需处理 |

### 🐛 Bug Fixes

- 去掉新版本检查的 24 小时本地缓存，改为每次交互运行实时向当前 registry 查询最新版本（最多等待 1.5 秒，超时或离线直接跳过），修复新版本发布后被 24 小时旧缓存挡住不提示的问题 (#55)。
- 发现新版本时的确认框默认值由「否」改为「是」，对齐 `yss-gen` 体验，直接回车即可通过 `npx --package=@yss-ui/create@<最新版本>` 切换到新版本继续后续创建选项 (#55)。
- 修复 `npx` 已启动但下载新版本失败（如断网、镜像包不完整）时导致整个创建流程中断的问题：子进程未进入 CLI 入口即非零退出时自动告警并退回当前版本继续创建，新版本运行期报错时提示可加 `--no-update-check` 重试 (#55)。
- 发版脚本将别名包 `create-yss-app` 与 `@yss-ui/create` 绑定同步发版：只要 `@yss-ui/create` 发版，`create-yss-app` 自动跟发并对齐至同一目标版本号与依赖版本范围 (#52)。

## v1.3.0

`2026-10-13`

### ⚠️ 行为变化与升级说明

| 项 | 以前 | 现在 | 需要做什么 |
| --- | --- | --- | --- |
| `@yss-ui/*` 依赖版本 | 沿用模板里写死的版本，可能是旧版 | 生成后自动升到最新版，保留原来的 `^`、`~` 前缀 | 想保留模板版本，加 `--no-sync-deps` |
| `pnpm-lock.yaml` | 沿用模板的锁文件 | 依赖版本有变化时自动刷新；刷新不了就删掉 | 锁文件被删时，首次使用前执行 `pnpm install` |
| AI Skills | 交互模式会问要不要同步，非交互默认不同步 | 生成后总是同步最新版，不再询问 | 同步需要联网，最长等 120 秒；失败只提示，不影响创建。没网时加 `--no-skills` |
| 模板自带的 skills 同步和「下一步」提示 | 模板自己同步 skills，再打印一份「下一步」 | CLI 让模板跳过这两步，统一由 CLI 负责 | 无需处理。模板更新前仍会看到模板的 skills 警告和它那份「下一步」，skills 也可能同步两次 |

### 🚀 Features

- 生成后自动把 `@yss-ui/*` 依赖升到最新版。用镜像时，如果镜像还没同步最新版，就用镜像上能装到的最高版本 (#53)。
- 查版本时每个包最多等 5 秒，总共最多 15 秒；查不到就保留原版本。`--offline` 时不查 (#53)。
- 生成后自动同步最新 AI Skills，模板带了校验脚本就顺便检查一遍。同步需要联网，最长等 120 秒；失败只提示，不影响创建 (#54)。
- 预览表新增「依赖版本」一行，显示会从哪个源查版本（会读取模板 `.npmrc` 里配的源）；`--json` 输出新增 `dependencyUpdates`、`lockfile`、`skills` 字段 (#53, #54)。

### 🐛 Bug Fixes

- 不再出现两条「skills 未自动同步」警告和两份「下一步」提示，也不再提示 `pnpm install --frozen-lockfile`。需要模板同时更新 (#54, #53)。
- 交互模式下的警告现在会显示出来 (#54)。

## v1.2.0

`2026-10-12`

### 🚀 Features

- **启动时显示版本号**：交互模式标题显示版本（如 `YSS 微应用创建 v1.2.0`）；非交互模式在 stderr 打印 `create-yss-app v1.2.0`；所有 `--json` 输出（含失败结果）新增 `cliVersion` 字段 (#52)。
- **新版本提示与切换**：启动时在后台查询当前 registry 上 `@yss-ui/create` 的最新版本 (#52)。
  - 交互模式：第一个问题前提示「当前 1.2.0 → 最新 1.3.0」并询问是否切换，默认「否」；选「是」通过 `npx` 下载新版本，带上原参数接着创建。不会未经确认自动升级。
  - 非交互模式：不等结果；流程结束时如果已查到新版本，打印提示框「下次请用 npm create yss-app@latest」。
  - 预发布版（版本号带 `-`）不算新版本；最新版本号在本地缓存 24 小时，切换 registry 后重新查询。
  - 查询超时 1.5 秒，离线或请求失败时直接跳过。
  - 没有交互终端、`--json`、`--dry-run`、`--offline`、`CI=true` 时不检查；新增 `--no-update-check` 参数，也可设置 `YSS_CREATE_NO_UPDATE_CHECK=1` 手动关闭。
  - 只发 GET 请求读取公开的版本元数据，不上报任何信息。

### 📝 Docs

- 别名包 `create-yss-app` 同步发布 1.2.0，README 补充「请始终带上 `@latest`」。1.1.0 的别名包依赖固定解析到 `@yss-ui/create@1.1.0`，不同步发版的话，npx 缓存过 1.1.0 的用户执行 `npm create yss-app@latest` 仍会跑旧版本。
- 常见问题新增「运行的不是最新版本」：如何确认版本、镜像同步延迟时临时指定官方源、删除全局安装的旧版本、清理 npx 缓存 (#52)。

> 1.1.0 及更早版本没有新版本检查。本机缓存了这些版本时（例如执行 `npm create yss-app` 仍出现 OpenAPI 提问），需要先执行 `rm -rf ~/.npm/_npx` 清理一次，并改用 `npm create yss-app@latest`。

- **出错时转圈不收尾**：交互模式下模板拉取失败后不再残留转圈状态 (#51)。

## v1.0.0

`2026-10-10`

### 🚀 Features

- **初始发布**: 企业级微应用一键脚手架 CLI (`@yss-ui/create` 与别名包 `create-yss-app`)。
- **activeRule 规则统一**: 统一为雨燕驼峰命名规则，支持从应用英文名自动推导单段路由；名称含数字导致驼峰不合法时自动退回短横线形式（`app-1 → /app-1`、`crm2 → /crm-2`）。
- **模板共享核心**: 与 `yss-create-microapp` AI Skill 共享零外部依赖 core 模块，生成结果逐文件一致。
- **自动化支持**: 支持 `--dry-run`、`--json`、`--plan-out` 与 `--apply` 离线可审阅计划执行。
  - `--json` 时 stdout 只输出一行 JSON，CLI 日志与模板脚本输出全部走 stderr。
  - `--plan-out` 只写出计划文件、不拉模板、不生成项目；由 `--apply` 执行。
  - `--apply` 校验 sha256 后仍会按当前规则重新校验全部参数；计划文件损坏/缺失、签名不符、参数非法、目标目录已存在统一退出码 4。
- **参数严格校验**: 未知或拼错的参数（如 `--dryrun`）、多余位置参数、`--pm` 非 `pnpm|npm|yarn` 均退出码 2。
- **无遥测**: 不收集任何数据。
